# SPB MAP — исследование исторических персон, адресов и социальных связей Санкт-Петербурга

Аналитический отчёт • 6 ноября 2026 года • На основании технического задания, реестра SPB MAP и открытых интернет-источников

## 1. Основные выводы

SPB MAP целесообразно развивать не как каталог знаменитых жильцов, а как историко-биографический граф, в котором каждое утверждение о человеке, месте и времени связано с проверяемым свидетельством.

Проверка обнаружила три принципиально разных слоя источников:

- Массовые адресные источники: дореволюционные и советские справочники «Весь Петербург», «Весь Петроград», «Весь Ленинград». Они позволяют строить большие массивы упоминаний людей, профессий, учреждений и адресов.
- Источники документального подтверждения: государственные архивы, музейные собрания, личные документы, специальные исторические исследования. Они необходимы, чтобы отличать реальное проживание от регистрации, владения, работы и других отношений.
- Источники связывания идентичностей: биографические справочники и Wikidata. Их основная ценность — сопоставление людей между разными коллекциями, а не самостоятельное доказательство проживания.

Проверены оба обязательных проектных документа:

[Реестр 340 полей SPB MAP](https://github.com/kostyabanket/spb-city-map/blob/main/research/field-inventory-340.csv?utm_source=chatgpt.com) · [Исследовательский протокол ORCHESTRATION-V1](https://github.com/kostyabanket/spb-city-map/blob/main/research/ORCHESTRATION-V1.md?utm_source=chatgpt.com)

Реестр действительно содержит 35 основных полей и 305 тематических, причём ряд полей уже предусматривает исторических жильцов, годы проживания, владельцев, посетителей и мемориальные доски. Следовательно, расширение проекта не должно дублировать существующие атрибуты. Требуется прежде всего нормализовать многозначные связи, временные интервалы и доказательства.&#x20;

Уровень: надёжная вторичная публикация. Подлинная адресная запись за конкретный год в рамках проверки не извлечена.

Методическая ценность — разграничение архитектора здания, жильца и лица, которому посвящена мемориальная доска. Одна личность может иметь все три роли, однако они должны храниться независимо.

## 5. Новые направления модели данных

Сопоставление с реестром показывает: расширять SPB MAP лучше через специализированные связанные таблицы или коллекции, а не через сотни дополнительных колонок в основной карточке здания.

Предлагается десять структурных расширений. Их структурированное представление не обнаружено среди просмотренных полей; отдельные аналогичные сведения уже присутствуют в CSV.

| Новая сущность или функция   | Главное назначение                                  | Приоритет |
| ---------------------------- | --------------------------------------------------- | --------- |
| `Person`                     | Независимый идентификатор личности и варианты имени | P0        |
| `ResidenceEpisode`           | Отдельные периоды проживания по адресу              | P0        |
| `PersonPlaceRelation`        | Типы связи человека с местом                        | P0        |
| `EvidenceAssertion`          | Утверждение с документом и уровнем доказанности     | P0        |
| `HistoricalAddressVersion`   | Исторические адреса с периодами действия            | P0        |
| `IdentityMatch`              | Сопоставление исторических личностей                | P0        |
| `Household`                  | Состав исторического домохозяйства                  | P1        |
| `TemporalSocialOverlap`      | Вычисленное соседство по месту и времени            | P1        |
| `BiographicalTimeline`       | Хронология мест, организаций и событий              | P1        |
| `MemorialAccuracyAssessment` | Проверка мемориальной атрибуции                     | P2        |

Принципиально: `EvidenceAssertion` не заменяет существующие `people_079` и `provenance_274`–`provenance_278`, а позволяет хранить несколько независимых свидетельств одного факта.

### Предлагаемая структура исторического графа

Концептуальная схема. Каждое ребро должно иметь собственную временную и доказательную характеристику; стрелки здесь не отражают полноценную базовую схему.

Пример минимальной машиночитаемой записи:

```

{
  "person_id": "person:kirov",
  "place_id": "building:benois",
  "relation_type": "RESIDED_AT",
  "unit": "20",
  "valid_from": {
    "value": "1926-04",
    "precision": "month"
  },
  "valid_to": {
    "value": "1934-12-01",
    "precision": "day"
  },
  "evidence": [
    {
      "type": "museum_publication",
      "url": "https://spbmuseum.ru/exhibits_and_exhibitions/permanent_displays/1323/",
      "status": "secondary_source"
    }
  ],
  "review_status": "needs_primary_source"
}

```

Здесь идентификаторы `person:kirov` и `building:benois` — иллюстративные, не установленные ID SPB MAP.

Модель следует дополнить полями внутреннего хранения `assertion_id`, `source_id`, `document_locator`, `asserted_at`, `retrieved_at`, `confidence`, `conflict_group_id` и `reviewed_by`. Они являются частью предлагаемых структур, а не новыми подтверждённо существующими колонками.

## 6. Методология идентификации людей и исторических адресов

### 6.1. Person Entity Resolution

Совпадение фамилии и адреса не должно приводить к автоматическому слиянию персон.

Предлагаемая последовательность:

1. Сохранить исходное написание имени без изменений, включая дореформенную орфографию.
2. Создать нормализованные варианты и выделить имя, отчество, фамилию, инициалы и титулы.
3. Сформировать кандидатов на совпадение по имени, времени, профессии, организациям и адресам.
4. Проверить несовместимости: годы жизни, семейные отношения, одновременные документированные занятия и другие признаки.
5. Сохранить решение вместе с основаниями, не удаляя исходные записи.

Для такой проверки полезна модель двух независимых оценок:

- `identity_confidence` — насколько вероятно, что две записи относятся к одному человеку.
- `assertion_confidence` — насколько доказано конкретное утверждение, например проживание по адресу.

Человек может быть идентифицирован с высокой уверенностью, но его связь с конкретным домом — лишь предположительно.

Рекомендуемые состояния: `CONFIRMED`, `PROBABLE`, `POSSIBLE`, `UNRESOLVED`, `CONFLICTED`. Это проектируемый словарь, а не существующие значения SPB MAP.

### 6.2. Историческая адресация

Нормализованный современный адрес и исторический адрес — разные объекты данных.

Алгоритм должен проходить через цепочку:

`Исходный адрес → историческая улица → период названия → домовладение → корпус/здание → современный объект SPB MAP`

Архивная выставка «Городские имена сегодня и вчера» содержит конкретные материалы о переименованиях, в том числе решения 1944 года с архивными шифрами. Она может служить источником для построения временного справочника топонимов, но не заменяет исторические планы и данные нумерации.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://spbarchives.ru\&sz=32)

Архивы Санкт-Петербурга+1



Предлагаю отдельно оценивать точность соответствия: квартира, корпус, здание, домовладение, улица, квартал или район. Если достоверно определена лишь улица, показывать точную точку на здании нельзя.

### 6.3. Правило доказательства проживания

Минимальные уровни:

| Степень | Основание                                               | Что можно утверждать                               |
| ------- | ------------------------------------------------------- | -------------------------------------------------- |
| A       | Прямой первичный документ с адресом и датой             | Документ подтверждает соответствующий факт         |
| B       | Независимые согласующиеся свидетельства                 | Высокая уверенность при проверенной идентичности   |
| C       | Атрибутированное музейное или научное исследование      | Надёжное вторичное утверждение                     |
| D       | Отдельная адресная запись или вторичная публикация      | Документальное упоминание, требующее интерпретации |
| E       | Фамилия, косвенное совпадение, алгоритмическая гипотеза | Нельзя публиковать как установленное проживание    |

Существенно, что архивный документ тоже может содержать ошибку. Поэтому класс документа и качество конкретного доказательства следует оценивать независимо.

## 7. Три практических пилота интеграции

Пилот A. Адресная книга → записи персон

В качестве первого тестового материала подходит выпуск «Весь Петербург» за 1903 год, доступный через НЭБ.

Конвейер: получение разрешённого экземпляра → OCR → разметка разделов и колонок → извлечение ФИО, занятий, адресов → сохранение страниц → дедупликация → редакторская проверка.

Измерять: точность распознавания имён, адресов, профессий, долю записей с исходной страницей и количество ложных объединений персон.

Начальная тестовая выборка: 200–500 записей, отобранных из нескольких разных разделов. Это предлагаемая выборка, а не уже выполненный импорт.

Пилот B. Исторический адрес → современный объект

Использовать дом трёх Бенуа, дом Лидваля, адрес на Кузнечном и архивные примеры переименования улиц.

Измерять: долю подтверждённых сопоставлений на уровне здания, долю неоднозначных адресов, количество случаев ручной проверки и ошибок привязки.

Результат — отдельный справочник `HistoricalAddressVersion`, связывающий исторические адресные свидетельства с `place_id` только при достаточных основаниях.

Пилот C. Исторический социально-пространственный граф

Начальная выборка — жители дома Бенуа, связанные с ними организации и другие документально установленные адреса.

Разделить подтверждённые социальные отношения, совместное проживание и вычисленное соседство.

Измерять: число проверенных узлов и связей, долю связей с доказательствами, долю временно определённых отношений и качество ответов на запросы пользователей.

Возможный результат — интерактивная карта биографий с историческим временным фильтром.

### Варианты пользовательского интерфейса

В перспективе SPB MAP может отвечать на вопросы «Кто жил здесь в 1912 году?», «Где жил Достоевский в разные периоды?», «Какие писатели жили в одном квартале?» и «Какие адреса подтверждены первичными документами?».

При этом система должна явно показывать разницу между «встречались друг с другом» и «оказались соседями в один период».

Энциклопедии и музеи: тексты полезны для проверки исторических отношений, но разрешение на их массовое копирование не подтверждено. Допустимость извлечения фактов, сохранения фрагментов, использования изображений и автоматических запросов необходимо оценивать отдельно.

В технической реализации рекомендованы три режима:

| Режим    | Условие                                                                           |
| -------- | --------------------------------------------------------------------------------- |
| `IMPORT` | Есть разрешённый способ получения данных, ясные права и проверяемое происхождение |
| `REVIEW` | Данные можно исследовать, но интерпретация требует редактора                      |
| `LINK`   | Можно дать ссылку на оригинал без копирования его содержания                      |

Для персональных данных необходимо установить отдельную политику ограничения доступа к сведениям о живущих и потенциально живых людях. Исторический характер документа не означает, что каждый упомянутый в нём человек уже умер.

## 10. Приоритетные рекомендации SPB MAP

P0

Существующие поля основной карточки здания сохранить как представление над структурированными данными.

## 11. Заключение

У SPB MAP есть реальная основа для формирования исторического графа Санкт-Петербурга. Существуют массовые адресные источники, специальные музейные исследования, архивные указатели домовых книг и машиночитаемые биографические идентификаторы.

Наиболее ценный результат исследования — обнаружение возможности соединить эти ресурсы без сведения разных исторических свидетельств к одному неподтверждённому текстовому полю.

При этом центральной сущностью будущей модели должна быть не только историческая персона, а проверяемое утверждение о её связи с конкретным местом во времени.

Такой подход позволит в перспективе исследовать не только знаменитых жителей Петербурга, но и профессиональные сообщества, домохозяйства, социальную географию и изменение состава городского населения.

Текущий результат представляет собой документально обоснованную разведку источников и проектную методологию. Для полноценной оценки массового наполнения следующим решающим этапом остаётся ограниченный эксперимент с реальными страницами адресных книг и архивными записями.

Все предложенные действия аналитические. Репозиторий, Google Таблицы, текущая схема SPB MAP и опубликованные данные не изменялись.
