# SPB MAP — проверка реализуемости на реальных данных

Техническая проверка источников • 6 ноября 2026 года • Только чтение, без изменений проекта

## 1. Результат проверки

Проверены пять направлений источников. Главный результат — найдены реальные идентификаторы, документированные способы получения данных и конкретные значения, позволяющие спроектировать небольшие интеграции.

При этом пять полностью подтверждённых конвейеров импорта пока не получены: для городского портала не удалось проверить актуальную карточку набора, для OpenStreetMap — непосредственно прочитать объект через API, а для GBIF — извлечь конкретную запись наблюдения внутри Петербурга.

| Источник            | Что удалось подтвердить                                | Статус           |
| ------------------- | ------------------------------------------------------ | ---------------- |
| Городской open data | Исторический ID 69, формат API                         | Частично         |
| OpenStreetMap       | Конкретный OSM relation ID, схема получения            | Частично         |
| Wikidata            | Q-ID, реальные значения, JSON, лицензия                | Подтверждено     |
| GBIF                | UUID набора, виды, территория, метод геопривязки       | Частично         |
| Промышленный архив  | Фонд, опись, номера дел, даты и сведения о предприятии | Каталог проверен |

Различаю три состояния: подтверждено — значение непосредственно видно в источнике; частично — подтверждён идентификатор или интерфейс, но не прочитан конечный набор; предлагается — схема будущего пилота, а не уже созданные данные.

Это полезный тест не для карты отдельных зданий, а для самостоятельного экологического слоя, в котором доказательством является научная публикация и географическая область наблюдения.

## 3. Три пилота — каждый до 10 записей

```

  "external_ids": {
    "wikidata": "Q2367357",
    "osm_relation": "1576204"
  },
  "match_status": "review_required",
  "source_url": "https://www.wikidata.org/wiki/Q2367357"

```

Значения внешних ID относятся к Новой Голландии. `spb_place_id` — заполнитель: реальный идентификатор в проекте здесь не устанавливался.

Критерии приёмки: четыре корректно сопоставленные карточки; отсутствие ложных совпадений; источники у всех новых значений; сохранение существующих `place_id`; отсутствие изменений первоначальных записей.

### Пилот B. Новый тематический слой «Городская биология»

До 8 наблюдений • объекты за пределами зданий

Задача — доказать, что SPB MAP способен хранить самостоятельные природные наблюдения с датами, географической неопределённостью и научными источниками.

Начальная коллекция: GBIF `e52aacbf-c701-462b-b68f-346502fbc270`.

### Процедура формирования восьми записей

1. Получить до 8 записей через GBIF Occurrence API, используя подтверждённый UUID набора.
2. Оставить только наблюдения, пространственно попадающие в Санкт-Петербург.
3. Проверить `gbifID`, вид, координаты, дату или год публикации, источник и неопределённость координат.
4. Исключить записи с ошибочной географией и недостаточной доказательностью.
5. Представить оставшиеся точки на отдельном исследовательском слое, без связывания с ближайшими зданиями.

Минимальная схема одной записи:

| Поле SPB MAP            | Поле GBIF                       |
| ----------------------- | ------------------------------- |
| `observation_id`        | `gbifID`                        |
| `species_name`          | `scientificName`                |
| `observed_at`           | `eventDate`                     |
| `latitude`              | `decimalLatitude`               |
| `longitude`             | `decimalLongitude`              |
| `spatial_uncertainty_m` | `coordinateUncertaintyInMeters` |
| `source_reference`      | `references` / `datasetKey`     |
| `evidence_type`         | `basisOfRecord`                 |

Это соответствие полей — проектная схема. Восемь индивидуальных GBIF-записей ещё не извлечены и не должны считаться подтверждёнными.

Критерий приёмки: до восьми реальных наблюдений с проверенными ID, координатами, датами и условиями использования. Если в выбранном наборе их меньше, пилот публикует фактическое число, не дополняя выборку искусственно.

## 5. Окончательный вывод и рекомендация SPB MAP

Реализуемость подтверждена неравномерно, но достаточно, чтобы определить конкретный следующий технический эксперимент.

Я бы начал с пилота C — «Красный треугольник». Это самый сильный доступный пример: есть два идентификатора Wikidata для разных сущностей, опубликованный архивный фонд, реальные производственные характеристики, датированные организационные изменения, исторический адрес и отдельное дело с планом территории.

Вторым запускал бы пилот A, поскольку он проверяет главное архитектурное ограничение — можно ли обогащать существующие объекты без изменения 340 полей. Пилот B следует начинать после того, как будет проверена фактическая выдача GBIF и извлечены индивидуальные `gbifID`.

Что доказано: внешние источники действительно позволяют связать независимые городские сущности и конкретные исторические свидетельства. Что ещё не доказано: стабильность всех API, наличие подходящих записей по каждому из четырёх объектов, юридическая возможность автоматического импорта и качество массового сопоставления.

Репозиторий GitHub, таблицы, существующие 340 полей и данные SPB MAP не изменялись. Все три пилота выше являются ограниченными спецификациями проверки, а не запущенным импортом.
