# SPB MAP — Алгоритм наполнения карточек по адресу v1.0
**Дата:** 2026-11-06 · **Статус:** спецификация для первого парсера, не объявление о готовом исполняемом сервисе.

## Задача
Подаём адрес (и при необходимости название и известный `place_id`). Парсер выбирает **только релевантные разрешённые источники**, извлекает атомарные сведения, сохраняет ссылки и версии, проверяет принадлежность точного объекта и готовит **черновик карточки** по [схеме рубрик](../schema/CARD-RUBRICS-V1.md) / [карте 340 полей](../schema/RUBRIC-MAP-340-2026-11-06.csv). На первом проходе — **Петроградский район Санкт-Петербурга**. Никакой автоматической публикации и выдуманных данных.

**Машинно-читаемый справочник источников:** [SOURCE-REGISTRY-PETROGRADSKY-V1.json](./SOURCE-REGISTRY-PETROGRADSKY-V1.json). В нём не каждый источник означает готовый API: `access_status` и `automation` определяют, можно ли запускать автоматическое чтение.

## 1. Контракт запуска
```json
{
  "address": "Большой проспект Петроградской стороны, 104",
  "place_id": "SPB-PET-0002",
  "name_hint": "Двор-Бэтмен",
  "object_type": "courtyard",
  "district": "Петроградский район",
  "mode": "dry_run",
  "max_sources": 8,
  "max_claims": 30
}
```
`place_id` обязателен для обогащения существующей карты. Для нового адреса без `place_id` — только отдельный `candidate_id` и статус `NEW_CANDIDATE_FOR_REVIEW`, **без публичного ID**.

## 2. Последовательность (строго по этапам)
1. **Вход и географическая рамка.** Уточнить район: Петроградский административный район, не «историческая Петроградская сторона». Если проверенная геометрия административной границы отсутствует, `district_check=PENDING`, новую точку не создавать и не публиковать. Никакого грубого прямоугольника как юридической границы.
2. **Паспорт из собственного проекта.** Проверить существующий `place_id` в таблице и `properties.id` в GeoJSON. Сохранить точный адрес, координаты, тип (`courtyard / building / complex / organization`), предыдущие поля. Для существующих четырёх считать их identity-lock; не исправлять автоматически.
3. **Поисковые ключи.** Сгенерировать варианты адреса (пр./проспект, П.С., литера, корпус, старый номер), но сохранить **original-address** и период. Никогда не отождествлять объект только по прозвищу и совпадающему номеру дома. Особое правило `0002`: **Дидерихс, Большой пр. П. С. 104, НЕ Иоффе, Рубинштейна 40/11**.
4. **Маршрут источников по рубрикам.** Начать с P0 проекта, затем P1 Commons, Wikidata при уже подтверждённом QID, КГИОП/РГИС как официальные записи; P2 архив и музей, OSM только в пределах допустимого доступа и на уровне конкретного объекта; P3 вторичные сайты и PastVu — чтение/ссылка, если права на копирование неизвестны. `HOLD` GBIF и городской набор 69 не запускать.
5. **Адаптеры.** Каждый адаптер возвращает сырой `SourceRecord`: `source_id, provider_id, url, fetched_at, http_status, content_type, origin_title, date, archival_locator, licensed_reuse_status, source_snapshot_hash`. Если документ не прочитан, сохранять лишь `CATALOGUE_ONLY`, не `PRIMARY_READ`.
6. **Извлечение фактов без «воды».** Выделить отдельные высказывания из проверенных фрагментов: субъект, предикат, значение, дата/интервал, место в документе, точный адрес/корпус и ссылка. Сохранить `verbatim_fragment` или короткий первичный смысл (без длинного копирования лицензированного текста) и `display_summary`; не размывать точность пересказом.
7. **Связать с сущностью, а не только адресом.** Каждый факт применим к двору, дому, корпусу, ансамблю, организации, человеку или охраняемому объекту. Если источник описывает дом Занина, не приписывать все свойства автоматически его восьмиугольному двору. Для Бенуа/Лидваля корпусность отдельно. При невозможности доказать субъект — `MATCH_UNCERTAIN`.
8. **Дедупликация и противоречия.** Ключ `subject_id + predicate + time_scope + source_record_id + normalized_value`. Совпадающий факт из разных независимых источников **не теряет вторую ссылку**. Противоречия — в отдельных версиях со статусом `CONFLICT`, без голосования ИИ за истину.
9. **Достоверность + права + публикация — разные проверки.** `source_quality`, `claim_confidence`, `viewpoint_match`, `media_rights_status`, `editorial_review`, `publish_gate`. Фото Commons проверять по конкретной карточке файла: автор/лицензия/атрибуция; с PastVu без права на размещение — только ссылка. У жителей раздельно `RESIDED_AT`, `OWNED_PROPERTY_AT`, `VISITED`.
10. **Сборка карточки.** Проецировать утверждения в рубрики `rubric_id`. В шапке оставить краткую выжимку (не сырой скопированный абзац). В раскрывающихся разделах показывать только содержательные данные. При отсутствии доказательств не заполнять рубрику текстом по догадке.
11. **Dry-run и QA.** Выдать список новых/изменённых утверждений, источники, конфликты, пустоты, сколько рубрик получилось. Проверить существующие ID и не изменённость 35 legacy-полей. Присвоить заявке `READY_FOR_EDITOR` только после проверки ключевых совпадений; `READY_FOR_PUBLISH` — отдельная стадия с правами и утверждением.
12. **Запись исключительно в research/staging.** Создавать кандидат-файлы и отчёт сверки. В `main`, Google Таблицу, публичный GeoJSON и сайт **не писать по умолчанию**. Публикация только через код/редакционный workflow; отсутствие свежего фото или архива не должно мешать наполнению остальных рубрик.

## 3. Разрешённые адаптеры и источники (первый проход)

|Очередь|Провайдер|Какие данные|Режим|Проверка|
|---|---|---|---|---|
|0|SPB MAP 35 полей + публичный GeoJSON|паспорт, четыре ID, уже опубликованный текст|read-only, внутренний|identity-lock|
|1|**КГИОП, РГИС**|статус охраны, официальные юридические объекты, зона/границы|ручная сверка / разрешённый открытый экспорт|нельзя присвоить мемориальный ID ансамблю|
|1|**Wikimedia Commons**|современные/исторические изображения, права, метаданные|точечный MediaWiki `imageinfo` по ID файла|автор ≠ всегда загрузивший; лицензия на каждое фото|
|1|**Wikidata**|QID и внешние идентификаторы, кандидаты атрибутов|точечный EntityData JSON по подтверждённому QID; SPARQL лимитировать|тип объекта + адрес + источники утверждений|
|2|**OSM**|геометрия/теги конкретных объектов|только разрешённый точечный lookup, лицензия ODbL; кэш|way/relation пока не доказаны для четырёх|
|2|**Архивы СПб, РНБ, музей**|жильцы, годы, корпуса, планы, события|каталог/ручная проверка; доказательные локаторы|скан не читался ≠ оригинал подтверждён|
|3|**Citywalls, Петербург24**|истории, прозвища и детали|ссылки и краткие проверяемые утверждения|не превращать легенды в факты|
|3|**PastVu**|исторические фото|ссылка/метаданные, не самостоятельная публикация файла|права на фото отдельно|
|HOLD|Городские данные №69, GBIF|позднейшие тематические слои|не запускать|нет проверенных текущих строк/API/GBIFID|

**Ограничения внешних сервисов:** публичный Nominatim не является свободным массовым геокодером; запрещён автокомплит и систематические выгрузки, есть строгие rate limits и требования к User-Agent/атрибуции. Для крупного масштаба нужен собственный извлекатель OSM/провайдер с договором, а не бесконечные запросы к общедоступному серверу. Wikidata WDQS — ограниченная по времени/частоте публичная служба, использовать точечные QID и кэш. У Commons `imageinfo extmetadata` может быть HTML и дорогим запросом, поэтому только несколько файлов одновременно.

## 4. Формат результата
```text
research/runs/<run_id>/
  input.json
  source-records.jsonl          # 1 запись на реально прочитанный источник
  candidate-assertions.jsonl    # 1 утверждение = 1 отдельный субъект/ссылка/дата
  media-candidates.jsonl        # author, file_page, license, rights, match
  entity-links.jsonl            # дом — содержит — двор / корпус — часть — ансамбль
  card-preview.json             # только непустые рубрики и лид
  qa.json                       # matches, conflicts, unknowns, blocked, coverage
```
Все записи содержат `retrieved_at`, `provider_id`, `source_status` и `review_status`. Историческая дата != дата загрузки документа != дата проверки.

Пример атомарного результата (строка-идея, **НЕ результат свежего парсинга**):
```json
{
  "place_id": "SPB-PET-0002",
  "subject_type": "building",
  "predicate": "associated_with_courtyard",
  "value": "Доходный дом Р. А. Дидерихса",
  "source_id": "SPB_MAP_EXISTING_GEOJSON",
  "identity_match": "PROJECT_SELF_ASSERTED",
  "primary_document_seen": false,
  "review_status": "REVIEW",
  "publish_gate": "NOT_AUTOMATIC"
}
```

## 5. Приёмочные тесты первого парсера
- Запуск `0002` не связывает объект с домом Иоффе и GUID Рубинштейна 40/11. При конфликте выдаёт `REJECT_FALSE_JOIN`.
- Запуск `0001` различает описание здания Занина и внутреннего восьмиугольного двора; камера фото `UNKNOWN`.
- `0003` не присваивает одному номеру ОКН правовой статус всего ансамбля Бенуа.
- `0011` не сливает «комплекс с садом и оградой» и «фасады» как один объект охраны.
- Чудов: `1930` — дата **выбытия**, не вселения. Владелец/житель не подменяют друг друга.
- 0 недоказанных `gbifID`, адресных GUID, OSM way/relation, юридических ID в статусе `VERIFIED`.
- По любому адресу вне проверенного Петроградского района новый объект не публикуется.
- Повторный запуск на том же адресе даёт ту же карточку и source IDs (`idempotent`), не порождает дублей.
- 35 legacy заголовков и исходные 4 `place_id` сохраняются; публичный GeoJSON и Google Sheet не затронуты.
- **QA-отчёт и исходные ссылки** воспроизводят, почему каждое утверждение появилось.

## 6. Что реально готово сегодня — а что нет
**Уже готово:** реестр всех 340 названий, аудит E, 35 совместимых legacy полей, 4 публичные карточки, P1 4 медиа-кандидата, P2 10 исторических утверждений, P3 8 промышленных утверждений, 15-источниковый маршрут и спецификация рубрик.

**Ещё не готово:** исполняемый адресный парсер с адаптерами, реально извлечённая официальная граница района, полноценный реестр прав каждого фото и верифицированные сканы архивных документов. Их нельзя выдавать за завершённую автоматизацию.

## 7. Реальная следующая инженерная задача
Реализовать `--dry-run --place-id SPB-PET-0002` с P0 + Commons + разрешёнными точечными провайдерами, с ограничением `max_sources`, кэшем, source IDs и детерминированным JSONL. На 4 объектах проверить отсутствие ложных совпадений, затем добавить адаптеры КГИОП и архива по одному после проверки условий доступа. Сайт читает **проверенную projection**, а не «скребёт сайты» при каждом открытии карточки.
