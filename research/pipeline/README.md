## Запуск на копии проекта

```bash
python research/pipeline/address_to_card_dryrun.py --dry-run --place-id SPB-PET-0002
python research/pipeline/address_to_card_dryrun.py --dry-run --address "Большой пр. П. С., 104"
python -m unittest discover -s tests -v
```

Выход — JSON в стандартный вывод, **без записи** в Google Таблицу, `data/places.geojson`, публикацию или пользовательские данные. Публикационные решения всегда отдельны. Не путать демонстрационный результат из известных материалов с фактическим новым веб-скрапингом.

## Контракт для настоящего коллектора

1. Запуск по адресу с подтверждённым точным совпадением административного района **Петроградский район**, не по одной надписи «Петроградская сторона». Для новых точек необходима подтверждённая официальная граница; сейчас она не загружена.
2. Сначала собственный реестр `place_id`; разбирать дом, двор, корпус, ансамбль, организацию и статус охраны как разные сущности.
3. Каждое новое поле = источник + дата/период + точное место документа + статус + права использования. `PRIMARY_READ` нельзя ставить, если прочитана лишь карточка каталога.
4. При каждом источнике сверяться с `automation` и `rights` в JSON-реестре; `HOLD` означает не запускать.
5. Сбор выполнять в кандидатные JSONL, строить краткий вывод в рубрики, скрывать пустые. Никаких новых публичных `place_id` и автоматических обновлений сайта.
6. QA: отрицательный пример **Рубинштейна 40/11 ≠ Дидерихс, Большой пр. П. С., 104**. У Чудова 1930 — выбытие, не вселение.

## Степень готовности
- Проверен формат карты 340 заголовков, список провайдеров и примеры.
- P0-адаптер проектирует существующие четыре места из локальных `data/places.geojson`, P1 CSV и `data/pilot-history.json`.
- **Ещё нет:** автоматического поиска и загрузки сайтов; официального GeoJSON полигона района; самостоятельной проверки прав каждого архивного изображения; публикационной интеграции. Это запланированные адаптеры, а не готовые функции.
